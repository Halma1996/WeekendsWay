# WeekendsWay (Qt 6.8 + CMake + QML)

Pet-project на **Qt / QML** для быстрого открытия часто используемых маршрутов и мест.

Проект для практики:
- **QML / Qt Quick Controls**
- **C++ ↔ QML интеграции**
- **сохранения данных в JSON**
- **сборки Android APK**
- **работы с внешним навигатором на Android и Desktop**

---

## Возможности

Приложение содержит 3 основных раздела:
- **Домой**
- **К друзьям**
- **Кушать**

Внутри разделов можно хранить списки адресов и мест, а затем быстро:
- открыть маршрут,
- открыть поиск места,
- использовать сохранённые данные повторно без ручного ввода.

В «Кушать» по умолчанию добавлены «Вкусно и точка», Rostic's, Burger King,
Papa John's, Pizza Hut и «Додо Пицца». Их кнопка навигации открывает поиск сети
на карте. Можно указать адрес конкретного ресторана через редактирование.
Существующие места сохраняются; стандартные места добавляются один раз,
поэтому удалённая пользователем запись не восстанавливается при новом запуске.

## Платформы

### Android
На Android приложение собирается в APK и открывает внешнюю навигацию через Android-механизмы запуска приложений.

Предлагаются только установленные и включённые Яндекс Карты, Google Maps и 2ГИС,
которые могут обработать ссылку. При открытии маршрута или поиска можно отметить
«Использовать по умолчанию». Настройка сохраняется в `maps.json`.
На главном экране кнопка «Карты: …» позволяет сменить приложение или вернуть
режим «Всегда спрашивать». Если выбранные карты удалены или отключены,
приложение снова предлагает доступные варианты. Если доступных карт нет,
отображается пояснение без перехода в браузер или магазин.

Для 2ГИС координаты вводятся в порядке `широта, долгота`; маршрут открывается
от текущего местоположения. Текстовый адрес передаётся в поиск 2ГИС: выберите
нужную точку и нажмите «Сюда». Это ограничение поддерживаемого 2ГИС deeplink.
В Яндекс Картах координаты также вводятся в порядке `широта, долгота` и
передаются в `rtext` как конечная точка маршрута. Текстовый адрес (в том числе
нераспознанная или неверная пара координат) открывается через параметр `text`:
выберите найденную точку, нажмите «Сюда» и выберите способ передвижения уже
в Яндекс Картах. Параметр режима маршрута `rtt` при поиске не передаётся.
Google Maps по-прежнему получает адрес непосредственно в ссылке на маршрут.

Официальный формат для Android:
[запуск Яндекс Карт по URL](https://yandex.ru/dev/yandex-apps-launch/maps/doc/concepts/yandexmaps-android-app.html).
В нём `rtext` описан как пары координат, а `text` — как поисковый запрос;
гарантированное геокодирование произвольного адреса в `rtext` не документировано.
Существующие режимы для координат сохранены: `pd`, `auto`, `mt`, `bc`.
Значение `bc` описано в [официальной документации параметров URL Яндекс Карт](https://yandex.ru/dev/yandex-apps-launch-maps/doc/ru/concepts/yandexmaps-web).
Android-документация перечисляет только первые три режима; фактическую обработку
велосипедного режима установленной версией приложения нужно проверить на устройстве.

Тесты выбора приложения, сохранения настройки и ссылок: `tests/navigation`.
Они запускаются GitHub Actions перед сборкой APK.

### Такси

В карточках друзей есть кнопка такси. В «Кушать» кнопок такси нет.
В «Домой» кнопка «Вызвать такси»
расположена между сохранением адреса и маршрутом. Кнопка передаёт адрес
выбранной записи, отдельно от настройки приложения карт по умолчанию.

Яндекс Go документирует конечную точку по координатам `end-lat` / `end-lon`:
[официальный формат ссылки](https://yandex.ru/support/taxi-distr/ru/api/deeplinks).
Пара `широта, долгота` передаётся сразу. Для текстового адреса Android Geocoder
асинхронно ищет до пяти вариантов; пользователь подтверждает точку перед
переходом в Go. Даже единственный результат требует подтверждения: геокодер
не гарантирует точность. В диалоге можно уточнить город, улицу и дом,
не изменяя сохранённую запись.

API-ключи и платные сервисы не добавлены. Поиск зависит от наличия системного
Geocoder и доступа к его службе; при ошибке показано пояснение и доступен
повторный поиск или ввод координат. Нет нового запроса к геопозиции и контактам.
Поиск и ожидание ответа выполняются вне UI, устаревшие ответы после отмены
игнорируются. Адреса и координаты не пишутся в журналы или новые файлы данных.
См. [Android Geocoder](https://developer.android.com/reference/android/location/Geocoder).

Открывается официальный HTTPS deeplink Go. Если Go не установлен или не
обрабатывает ссылку напрямую, официальный редирект ведёт в приложение либо
на его страницу в магазине. Начало поездки и тариф не навязываются; стоимость
и сам заказ пользователь подтверждает в Go. Тесты логики и UI не заменяют
проверку установленного Go и системного геокодера на физическом Android.

## Структура проекта

- `qml/` — интерфейс на QML
- `src/` — C++ логика
- `icons/` — иконки
- `android/` — Android-специфичные файлы, если используются
- `build/` — артефакты сборки (в репозиторий не добавляются)

Основные C++ классы:
- `Navigator` — открытие маршрутов и поисковых запросов во внешнем навигаторе
- `Storage` — сохранение и чтение пользовательских данных в JSON
- `Contacts` — чтение контактов Android с запросом разрешения и без блокировки интерфейса
- `Taxi` — поиск и подтверждение конечной точки для Яндекс Go

### Синхронизация контактов с друзьями

В разделе «К друзьям» нажмите «Синхронизировать контакты». Можно выбрать всю
телефонную книгу или отметить отдельные записи; список поддерживает поиск по
имени и номеру. Записи сохраняются только после подтверждения.

Импортируются имя, телефоны и первый основной почтовый адрес, если он указан.
Контакты без адреса тоже можно добавить; маршрут станет доступен после заполнения
адреса в карточке друга. Разрешение `READ_CONTACTS` запрашивается только при
запуске синхронизации. Запись в телефонную книгу и отправка контактов на сервер
не используются.

Синхронизация запускается вручную. Повторный импорт обновляет связанные записи
без повторного добавления. Изменённые вручную имя, телефон и адрес сохраняются,
как и домофон, этаж и квартира. Удаление контакта с телефона не удаляет карточку
друга; удаление друга не меняет телефонную книгу. Ранее добавленного друга можно
сопоставить по телефону либо по единственному совпадающему имени, если телефон ещё
не заполнен. При неоднозначном совпадении создаётся отдельная карточка.

Проверка логики объединения: `node --test tests/contact-sync.test.cjs`.
Поиск учитывает промежуточный текст Android-клавиатуры через `displayText`;
обновление модели сохраняет подходящие строки и выбранные контакты.
Проверка настоящего QML с `QInputMethodEvent`: `python3 tests/ui/test_contacts_search.py`
(тестовая зависимость: `PySide6-Essentials==6.8.3`).

## Navigator

Из QML доступны методы:

### `Navigator.openRoute(destination, travelMode)`
Открывает маршрут до указанного адреса или места.

Поддерживаемые `travelMode`:
- `"walking"`
- `"driving"`
- `"transit"`
- `"bicycling"`

### `Navigator.openSearch(query)`
Открывает поиск места или запроса в навигаторе / картах.

## APK через GitHub Actions (ветка Ai_brench)

Workflow `.github/workflows/android-apk.yml` собирает APK только по отдельному запросу.
Обычный push в **Ai_brench** пропускает сборку. Для запрошенной сборки в сообщение
коммита добавляется `[build apk]`; также поддерживается ручной `workflow_dispatch`.
Ветки **master** и **develop** не изменяются. Сборки используют Qt 6.8.3, JDK 17,
Android API 35, Build Tools 35.0.0 и NDK 26.1.10909125.
Qt устанавливается вместе с инструментами для Linux, необходимыми для сборки Android.

Как скачать APK:

1. Откройте вкладку **Actions** в репозитории.
2. Выберите **Build Android APK** и успешный запуск для ветки **Ai_brench**.
3. Внизу страницы в **Artifacts** скачайте **WeekendsWay-android-arm64-apk**.
4. Распакуйте ZIP и установите `WeekendsWay-arm64-v8a.apk` на телефон.

Это Debug APK для Android 9+ на устройствах **arm64-v8a**, с тестовой подписью.
Итоговый APK переподписывается постоянным ключом из секрета репозитория
`WEEKENDSWAY_SIGNING_JSON` (JSON с полями `keystore` в Base64, `password`, `alias`).
Закрытый ключ не хранится в git или кэше Actions. SHA-256 сертификата закреплён
в `android/signing-certificate.sha256`; сборка прекращается при отсутствии секрета
или несовпадении сертификата, вместо создания случайного ключа.

Идентификатор пакета остаётся `org.qtproject.example.WeekendsWay`. `versionCode`
увеличивается с новым запуском и попыткой: `1000000 + run_number * 100 + run_attempt`;
`versionName` имеет вид `1.1.<run_number>.<run_attempt>`. Повторный запуск старого
запуска остаётся старой версией и не предназначен для отката уже установленной новой.

Переход со старых APK со случайной подписью требует однократной переустановки,
так как их закрытые ключи не были сохранены. Удаление приложения стирает его данные.
Последующие APK с постоянным сертификатом устанавливаются как обновления.
Ключ в GitHub Secrets необходимо сохранять; его замена блокируется проверкой
отпечатка. Не помещайте ключ, пароль или JSON секрета в репозиторий или артефакты.
Артефакты доступны 30 дней. Для подписи нужен указанный секрет репозитория;
ключ или аккаунт для публикации в Google Play не требуется.

После успешной проверки подписи APK также сохраняется в ветке `Ai_brench`:
[`apk/WeekendsWay-latest.apk`](apk/WeekendsWay-latest.apk).
В папке `apk/` находятся текущая версия, ссылка на исходный коммит и сборку,
а также SHA-256 файла. Публикация выполняется отдельным заданием после сборки;
задание сборки остаётся с доступом только на чтение. Коммит APK содержит
`[skip ci]`, чтобы не запускать повторную сборку. Если ветка успела измениться,
публикация прекращается: сначала нужно собрать новый исходный коммит.

Для повторной сборки того же коммита откройте запуск и выберите **Re-run all jobs**.
Кнопка **Run workflow** требует наличия workflow в ветке по умолчанию;
пока это `master`, push в `Ai_brench` с маркером `[build apk]` — основной способ запуска.
